## 온보딩·인증 같은 교차 관심사 리다이렉트는 라우터 최상위 가드 한 곳에서 처리하고, 화면·셸·Provider는 서로 강결합하지 말고 각각 이미 병합된 계약만 소비하도록 증분 통합하라.
_[unverified, 60%, fix_loop]_

교차 관심사를 화면마다 중복 구현하면 각 화면의 커밋된 테스트가 서로 다른 기대를 굳혀 스펙과 충돌하고 P0로 중단되기 쉽다. 리다이렉트/가드를 단일 지점에 두면 테스트-스펙의 진실원이 하나가 되어 충돌이 사라진다. 또한 여러 화면이 앱 셸·Provider·공유 export를 동시에 소비하는 빅뱅 통합은 하나만 미완이어도 전체 빌드가 막혀 타임아웃한다. 데이터/로직 계층을 먼저 병합한 뒤, 각 화면을 개별 라우트로 lazy 마운트하고 라우트별 ErrorBoundary로 격리하면 미완 화면이 전체를 무너뜨리지 않아 안전하게 완성까지 밀 수 있다.

## 라우팅·Provider·전역 네비게이션은 단일 최상위 파일이 배타적으로 소유하도록 하나의 통합 패킷으로 합치고, 페이지 패킷들은 이 소유자에만 의존하게 하여 상호 대기 교착을 없애라.
_[unverified, 60%, fix_loop]_

개별 페이지가 각자 라우터/네비/Provider를 부분적으로 건드리면 통합 지점에서 서로를 기다리다 미완결·중복 마운트·컴파일 실패로 빌드가 깨진다. 앱 셸(라우팅 테이블, 전역 상태 Provider, 하단 탭바)의 소유권을 한 파일(App 루트)에 못박고, 외부 SDK 의존(광고·리워드 등)은 환경변수 미주입 시 크래시 없이 콘텐츠만 렌더하는 안전 폴백 래퍼로 감싸면, 통합 패킷이 다른 패킷 완료를 기다릴 필요 없이 독립적으로 컴파일·통과한다. 이는 어떤 미니앱에서도 '조립되지 않아 실패'하는 흔한 종단 실패를 예방한다.

## 라우팅으로 진입하는 모든 화면은 location.state·조회 결과가 없거나 손상돼도 크래시 없이 빈 상태를 렌더해야 하고, 알 수 없는 경로는 홈으로 리다이렉트해 스모크 타임아웃을 없애라.
_[unverified, 60%, fix_loop]_

직접 진입·새로고침·딥링크는 라우터 state를 비운 채 화면을 로드하므로, state.x를 무방비로 접근하면 렌더 중 예외가 나고 라우트 스모크가 크래시/timeout으로 실패한다. state를 옵셔널로 읽고 부재 시 안내+홈 이동 CTA의 빈 상태를 반환하며, App의 Routes에 catch-all(*→홈 리다이렉트)을 두면 미해석 경로의 무한 대기를 막을 수 있다. 또한 App/라우팅 진입점은 단일 패킷이 소유해야 병합 누락 시 경로가 통째로 해석 불능이 되는 사태를 예방한다. env 주입값(광고 ID 등)도 미설정을 전제로 방어해 렌더가 죽지 않게 하라.
