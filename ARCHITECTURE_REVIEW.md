# Architecture Review
Generated: 2026-08-09T20:12:58.571Z
Score: 52/100

## Summary
The core page/component/lib layering is reasonable (ScreenScaffold + Pre-built UI primitives + lib/storage + lib/domain), but the codebase is littered with scaffold/debug leftovers that reached production files, two parallel storage abstractions, and a large speculative 'contract.ts' type file that duplicates and conflicts with the real domain types. Cross-page boilerplate (toast state, id generation, haptic firing, AI-notice copy) is copy-pasted instead of shared, and several dead/unused files (probes, generic storage.ts, contract.ts) inflate the surface area without adding value.

## Issues
### Critical
- [consistency] Production navigation component ships debug diagnostics: console.log('DIAG ...') calls and globalThis pollution (`(globalThis as any).__ftbNavCtx = ...`) inside FloatingTabBar.tsx, which renders on every authenticated screen. — Files: src/components/FloatingTabBar.tsx / Fix: Strip all console.log/DIAG statements and globalThis assignments from FloatingTabBar.tsx before shipping; if test hooks are needed, inject them via a test-only wrapper/module mock instead of mutating globalThis in the component body.
- [duplication] Two independent localStorage abstractions exist: src/lib/storage.ts (getItem/setItem/removeItem, no error guarding) and src/lib/storage/base.ts (safeGetJSON/safeSetJSON + STORAGE_KEYS, used by all real domain storage modules). The former appears unused and shadows the latter's naming, risking someone importing the wrong one. — Files: src/lib/storage.ts, src/lib/storage/base.ts / Fix: Delete src/lib/storage.ts if unused (confirm with a repo-wide reference search), or if some code still needs a raw KV accessor, rename it clearly (e.g. rawKvStore.ts) and document why it doesn't use the safe*JSON helpers.
